# 타임라인 검토 프롬프트

당신의 임무는 사건 문서와 연표 문서를 검토하여 시간 충돌, 순서 오류, 형식 오류, 서술 충돌을 찾아내는 것이다.

이 작업은 **검토 단계**다. `raw/`는 참고용 원본 메모로만 보고, 그것을 직접 공개 타임라인으로 바꾸라고 지시하지 말 것. 먼저 `drafts/` 수준의 보정안과 검토 결과를 분리해 제시하라.
README의 개념적 `content/`는 공개 문서 묶음을 뜻하고, 현재 저장소의 Quartz 공개 입력은 `contents/`다.

## 입력

다음 입력만 사용한다.

- 대상 연표/사건 문서: `{{timeline_docs}}`
- 관련 raw 메모: `{{raw_timeline_notes}}`
- 관련 인물/장소/사건 문서: `{{related_docs}}`
- 이번 검토 범위: `{{review_scope}}`

## 참조 규칙

1. `schema/timeline-rules.md`를 최우선 기준으로 삼는다.
2. 형식 규칙은 `schema/entity-schema.md`도 함께 따른다.
3. README의 개념적 `content/`에 해당하는 실제 입력 `contents/`에 이미 존재하는 연표가 있으면, 정렬과 기준 연도를 우선 확인한다.
4. `drafts/`는 보조 참고만 하고, `raw/`는 원본 확인에만 한정한다.
5. 명시된 날짜가 없으면 추측하지 말고 범위를 줄여 말한다.

## 작업 절차

1. 각 문서의 `event_date`, `event_year`, `start_year`, `end_year`, `sequence`, `era`를 점검한다.
2. 같은 사건이 여러 연표에 중복되었는지 확인한다.
3. 연도 순서가 뒤집히거나, 동년 사건의 순서가 불분명한지 본다.
4. 사건의 원인과 결과, 전후 관계가 본문 서술과 메타데이터에서 일치하는지 확인한다.
5. 인간이 바로 수정할 수 있도록, 형식 문제와 의미 문제를 분리해서 적는다.
6. 필요하면 정렬된 후보 타임라인을 제시하되, 공개 문서 확정본으로 쓰지 말 것.

## 출력 형식

아래 순서를 지켜 한국어로 출력한다.

### 1. 총평

- 타임라인 전체가 안정적인지, 보정이 필요한지 요약한다.
- 충돌의 주된 유형을 한 문장으로 정리한다.

### 2. 형식 검사 결과

다음 항목을 각각 `통과 / 주의 / 실패`로 표시한다.

- 날짜 형식
- 연도 형식
- 범위 표기
- `sequence` 사용 여부
- frontmatter 존재 여부
- 파일명과 `slug` 일치 여부

### 3. 의미 검사 결과

다음 항목을 각각 정리한다.

- 시간 순서 충돌
- 같은 사건의 중복 서술
- 인물 생몰년과 사건 시점 충돌
- 연표와 본문 서술의 불일치
- 상대 시간 표현의 남용

### 4. 문제 목록

각 문제는 다음 형식으로 쓴다.

- `중요도`: `높음 / 중간 / 낮음`
- `위치`: 문서명 또는 사건명
- `문제`: 무엇이 잘못되었는지
- `근거`: 어떤 규칙과 충돌하는지
- `권장 조치`: 어떤 식으로 고칠지

### 5. 정렬된 후보안

필요한 경우에만, 오래된 사건부터 최신 사건 순으로 정리한 후보 타임라인을 제시한다.

- 같은 연도 사건은 `sequence` 또는 명시 순서로 고정한다.
- 날짜가 불명확하면 `추정`이라고 밝힌다.
- 새 사건을 임의로 추가하지 말고, 입력에 있는 사건만 재정렬한다.

### 6. 추가 확인 필요 사항

마지막에 사람 검토가 필요한 항목을 따로 적는다.

- 날짜가 아예 없는 사건
- 상호 모순되는 연도
- 동일 인물의 동시 다중 위치 서술
- raw와 content가 서로 다른 시간축을 말하는 경우
