# lore 검토 프롬프트

당신의 임무는 세계관 문서 묶음을 검토하여 설정 충돌, 누락, 중복, 표현 불일치를 찾아내고, 수정 방향을 제안하는 것이다.

이 작업은 **검토 단계**다. `raw/`는 원본 메모로만 참고하고, 그것을 곧바로 공개 문서로 변환하라고 지시하지 말 것. 필요하면 `drafts/` 수준의 후보만 제안하고, 공개용 `content/`(현재 저장소의 `contents/`)로의 확정은 하지 말 것.
여기서 `content/`는 README의 개념적 표기이며, 현재 저장소의 Quartz 공개 입력은 `contents/`다.

## 입력

다음 입력만 기준으로 판단한다.

- 대상 문서 묶음: `{{대상_문서}}`
- 관련 원문 메모 또는 발췌: `{{raw_참고}}`
- 참조해야 할 초안/공개 문서: `{{drafts_or_content}}`
- 이번 검토의 초점: `{{검토_초점}}`

## 참조 규칙

1. 최우선 기준은 저장소의 `schema/` 규칙이다.
2. README의 개념적 `content/`에 해당하는 실제 입력 `contents/`는 정리 완료본이므로, 같은 사실이 충돌하면 우선 참조한다.
3. `drafts/`는 중간 산출물이므로 보조 근거로만 본다.
4. `raw/`는 원본 메모이므로, 필요한 범위에서만 참고하고 최종 기준으로 삼지 않는다.
5. 추측이 필요하면 반드시 `추정`이라고 표시하고, 근거가 부족하면 단정하지 말 것.

## 작업 절차

1. 문서의 대상 범위를 확인한다. 한 문서가 한 엔티티나 한 주제만 다루는지 점검한다.
2. frontmatter, 파일명, `slug`, `title`, `type`이 schema와 맞는지 본다.
3. 관계, 이름, 용어, 시간 서술이 서로 충돌하는지 확인한다.
4. `raw/`에만 있는 정보와 README의 개념적 `content/`에 해당하는 실제 입력 `contents/`에 이미 반영된 정보를 구분한다.
5. 충돌이 있으면 원인을 설명하고, 어떤 기준 문서를 우선해야 하는지 정리한다.
6. 수정안을 제시하되, 공개 문서로 바로 전환하지 말고 `drafts/` 또는 검토 메모 수준으로 제한한다.

## 출력 형식

아래 순서를 지켜 한국어로 출력한다.

### 1. 총평

- 전체 상태를 한두 문장으로 요약한다.
- 이번 입력이 안전하게 확정 가능한지, 추가 확인이 필요한지 밝힌다.

### 2. 문제 목록

문제가 있으면 중요도 높은 순으로 나열한다.

각 항목은 다음 형식으로 쓴다.

- `중요도`: `높음 / 중간 / 낮음`
- `위치`: 문서명 또는 항목명
- `문제`: 무엇이 충돌하거나 부족한지
- `근거`: 어떤 문서나 규칙과 어긋나는지
- `권장 조치`: 어떻게 고칠지

문제가 없으면 `명시적 문제 없음`이라고 적는다.

### 3. 검토 기준별 결과

다음 항목을 별도로 구분해 적는다.

- 형식 일관성
- 시간 일관성
- 관계 일관성
- 용어 일관성
- 서술 일관성

각 항목은 `통과 / 주의 / 실패` 중 하나로 표시한다.

### 4. 수정 제안

실제 고칠 문장이나 구조를 짧게 제안한다.

- 필요한 경우 문장 단위로 예시를 든다.
- 확정되지 않은 내용은 대체안으로만 제시한다.
- 새 설정을 임의로 대량 생성하지 말고, 입력에서 지지되는 범위로 제한한다.

### 5. 추가 확인 필요 사항

다음과 같은 항목이 있으면 마지막에 정리한다.

- 서로 다른 출처가 충돌하는 사실
- 날짜나 연도처럼 확정값이 부족한 항목
- 관계의 방향성이나 대칭성이 불명확한 항목
- 공개 문서로 올리기 전에 사람 확인이 필요한 항목
