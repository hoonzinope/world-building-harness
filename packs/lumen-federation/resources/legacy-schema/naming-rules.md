# Naming Rules

이 문서는 저장소 전체에서 사용하는 이름 규칙을 정의한다.
핵심 목표는 파일명, slug, 제목, 참조 키가 서로 충돌하지 않도록 만드는 것이다.

## 적용 원칙

1. 파일명과 slug는 영어 기준으로 통일한다.
2. 제목은 한국어를 사용해도 되지만, 기계 처리 대상은 영어 slug로 본다.
3. 한 의미에 대해 여러 표기를 허용하되, canonical slug는 하나만 둔다.
4. 이름 규칙은 사람이 읽기 쉬움보다 일관성을 우선한다.

## 파일명 규칙

- 모든 문서 파일은 `lowercase-kebab-case.md`를 사용한다.
- 공백은 하이픈으로 바꾼다.
- 대문자는 사용하지 않는다.
- 특수문자는 제거한다.
- 중복 가능성이 있는 일반명사에는 더 구체적인 수식어를 붙인다.

예:

- `armin-vale.md`
- `helion-empire.md`
- `north-gate-district.md`

## slug 규칙

슬러그는 파일명과 같은 규칙을 따른다.

- 문자 집합: `a-z`, `0-9`, `-`
- 시작과 끝은 하이픈이 아니어야 한다.
- 연속 하이픈은 사용하지 않는다.
- 약어는 가능하지만, 의미가 불분명하면 풀어쓴다.

권장 정규식:

```text
^[a-z0-9]+(?:-[a-z0-9]+)*$
```

## 제목 규칙

- 제목은 사용자가 보는 표시명이다.
- 한국어 제목을 우선 허용한다.
- 필요하면 영어 부제를 병기할 수 있다.
- 제목은 slug를 그대로 쓰지 않아도 된다.

예:

- `# 아르민 베일`
- `# 헬리온 제국`

## alias 규칙

- 별칭은 검색 편의를 위한 보조 정보다.
- 표기 차이, 약칭, 옛 이름을 넣을 수 있다.
- alias는 canonical slug를 대체하지 않는다.
- alias에 파일명과 동일한 문자열을 반복해서 넣을 필요는 없다.

## 참조명 규칙

- 문서 간 참조는 `slug` 기준으로 작성한다.
- 링크 텍스트는 표시명, 목적지는 slug 경로를 사용한다.
- 참조 대상이 없으면 추측해서 만들지 말고 `drafts/` 또는 `raw/`에 남긴다.

예:

```md
[아르민 베일](../characters/armin-vale.md)
```

## 네이밍 우선순위

1. 존재하는 canonical slug 재사용
2. 의미가 정확한 영어 명사 사용
3. 필요 시 지역명, 조직명, 연도 등으로 구체화
4. 마지막 수단으로 접두사/접미사 추가

## 예시 frontmatter

```md
---
title: 북문 지구
type: location
slug: north-gate-district
aliases:
  - 북문
  - 북문구
---

# 북문 지구
```

## 검증 기준

- 파일명과 `slug`가 동일한 규칙을 사용한다.
- 파일명에는 공백, 대문자, 비영문 특수문자가 없다.
- `slug`는 영어 슬러그 정규식을 만족한다.
- `title`은 slug와 별개로 한국어를 허용한다.
- alias는 중복 없이 관리한다.
- 참조 링크는 존재하는 slug를 향해야 한다.
